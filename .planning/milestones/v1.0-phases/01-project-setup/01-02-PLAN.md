    .env.example
    .env.local

  <action>
    Create the Firebase initialization layer following the centralized singleton pattern from RESEARCH.md.

    1. Create `src/lib/firebase/config.ts`:
       - Export a `firebaseConfig` object that reads all 6 config values from `process.env.NEXT_PUBLIC_FIREBASE_*`
       - Keys: apiKey, authDomain, projectId, storageBucket, messagingSenderId, appId
       - Type the config using FirebaseOptions from 'firebase/app'

    2. Create `src/lib/firebase/clientApp.ts`:
       - Import firebaseConfig from './config'
       - Import { initializeApp, getApps, FirebaseApp } from 'firebase/app'
       - Use the getApps().length === 0 guard to prevent re-initialization
       - Export the firebaseApp instance

    3. Create `src/lib/firebase/auth.ts`:
       - Import { getAuth, Auth } from 'firebase/auth'
       - Import { firebaseApp } from './clientApp'
       - Export `const auth: Auth = getAuth(firebaseApp)`

    4. Create `src/lib/firebase/firestore.ts`:
       - Import { getFirestore, Firestore } from 'firebase/firestore'
       - Import { firebaseApp } from './clientApp'
       - Export `const db: Firestore = getFirestore(firebaseApp)`

    5. Create `.env.example` (committed to git, no secrets):
       ```
       # Firebase Configuration
       # Copy this file to .env.local and fill in values from Firebase Console
       # Firebase Console -> Project Settings -> General -> Your apps -> Web app
       NEXT_PUBLIC_FIREBASE_API_KEY=""
       NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN=""
       NEXT_PUBLIC_FIREBASE_PROJECT_ID=""
       NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET=""
       NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID=""
       NEXT_PUBLIC_FIREBASE_APP_ID=""
       ```

    6. Create `.env.local` with placeholder values (this file is gitignored by default):
       - Same keys as .env.example but with placeholder values like "your-api-key-here"
       - The user will replace these with real values from their Firebase Console

    IMPORTANT: Do NOT initialize Firebase eagerly at module scope if env vars might be empty. The clientApp.ts module should handle the case where config values are empty strings gracefully (it will fail when Firebase is actually used, which is fine for now -- the home page will detect this).
  </action>

    2. TypeScript compiles: `npx tsc --noEmit`
    3. `.env.example` exists and contains all 6 keys: `grep NEXT_PUBLIC .env.example | wc -l` should be 6
    4. `.env.local` exists: `test -f .env.local && echo "exists"`
    5. `.env.local` is NOT tracked by git: `git check-ignore .env.local` should show it's ignored
  </verify>
  <done>
    Four Firebase modules exist in src/lib/firebase/ with proper import chain (config -> clientApp -> auth/firestore). .env.example is committed as a template. .env.local exists with placeholder values. TypeScript compiles without errors.
