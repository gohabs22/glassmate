<objective>
Create the authentication infrastructure layer: Zod validation schemas, Firebase auth server actions (signup/login/logout), and a client-side AuthProvider context that tracks auth state with a loading guard.

Purpose: This is the foundation that all auth UI and protected routing depends on. Forms need validation schemas and server actions to call. Protected pages and conditional routing need AuthProvider to know if a user is logged in.
Output: Three modules -- validation schemas, server actions, and auth context provider -- ready to be consumed by auth forms and page routing.
</objective>

<task type="auto">
  <name>Task 2: Create auth server actions and AuthProvider context</name>
  <files>

  <action>
    1. Create `src/lib/firebase/auth-actions.ts` with `'use server'` directive:
       - `signup(state: SignupFormState, formData: FormData): Promise<SignupFormState>`:
         - Validate with SignupFormSchema.safeParse, return field errors if invalid
         - Call createUserWithEmailAndPassword(auth, email, password)
         - Return `{ errors: {} }` on success
         - Catch Firebase AuthError and map error codes:
           - `auth/email-already-in-use` -> email error "This email is already registered"
           - `auth/invalid-email` -> email error
           - `auth/weak-password` -> password error
           - default -> _form error "Failed to create account. Please try again."
       - `login(state: LoginFormState, formData: FormData): Promise<LoginFormState>`:
         - Validate with LoginFormSchema.safeParse
         - Call signInWithEmailAndPassword(auth, email, password)
         - Return `{ errors: {} }` on success
         - Catch Firebase AuthError:
           - `auth/user-not-found` and `auth/wrong-password` -> _form "Invalid email or password" (don't distinguish for security)
           - `auth/too-many-requests` -> _form "Too many attempts. Try again later."
           - default -> _form generic error
       - `logout()`:
         - Call signOut(auth)
         - Redirect to '/login' using next/navigation redirect

       IMPORTANT: Import auth from `@/lib/firebase/auth` (existing module from Phase 1). Import types from `@/lib/validations/auth`. Import Firebase auth functions from 'firebase/auth'. Cast errors as AuthError type.

    2. Create `src/components/auth/AuthProvider.tsx` with `'use client'` directive:
       - Define AuthContextType: `{ user: User | null; loading: boolean }`
       - Create AuthContext with createContext, default `{ user: null, loading: true }`
       - AuthProvider component:
         - useState for user (User | null, initial null) and loading (boolean, initial true)
         - useEffect with onAuthStateChanged(auth, ...) -- sets user and sets loading to false on FIRST callback
         - Cleanup: return unsubscribe from useEffect
         - Render AuthContext.Provider wrapping children
       - Export `useAuth` hook: `useContext(AuthContext)`
       - Import auth from `@/lib/firebase/auth`, User and onAuthStateChanged from 'firebase/auth'

       The loading state is critical: it starts `true` and goes `false` after the first onAuthStateChanged callback. This prevents components from rendering "not logged in" UI before Firebase has checked the persisted session.
  </action>
