  <action>
    Create `src/middleware.ts` (in the src/ directory, NOT inside app/) with lightweight cookie-based route protection.

    The middleware must:
    1. Check if the current path is a protected route (starts with '/dashboard')
    2. Check if the current path is an auth route (starts with '/login' or '/signup')
    3. Check for an auth session cookie. Use the cookie name `__session` (Firebase convention). Check with `request.cookies.has('__session')`.
    4. If protected route AND no auth cookie -> redirect to /login
    5. If auth route AND has auth cookie -> redirect to /dashboard
    6. Otherwise, NextResponse.next()

    Export a config object with matcher that skips static files and API routes:
    ```
    export const config = {
      matcher: ['/((?!api|_next/static|_next/image|favicon.ico).*)'],
    };
    ```

    IMPORTANT: Keep middleware lightweight. NO Firestore queries, NO Firebase Admin SDK calls, NO heavy computation. This is an OPTIMISTIC check only. The cookie check is just "does a cookie exist" -- not "is the token valid." Real verification happens in Server Components (future enhancement).

    NOTE: The `__session` cookie will be set by the client-side auth flow in Plan 03 after Firebase login succeeds. For now, the middleware is in place but the cookie won't exist yet, so /dashboard will redirect to /login (correct behavior for unauthenticated users).
  </action>
  <verify>

    2. Visit http://localhost:3000/login -> should render login page (no cookie, so no redirect)
    3. Visit http://localhost:3000/scan -> should render scan page (not protected)
  </verify>
  <done>

  </done>
