  <action>
    Create a new Xcode iOS App project using the command line or by generating the project structure manually:

    1. Use `xcodegen` or manual project file creation to set up an Xcode project named "BeerGlassApp" with:
       - Bundle identifier: com.beerglass.app
       - Minimum deployment target: iOS 16.0
       - Swift language
       - SwiftUI lifecycle (not UIKit AppDelegate lifecycle)

    2. Create the feature-based folder structure (NOT file-type folders at root):
       ```
       BeerGlassApp/
       ├── App/                    # App entry point files
       ├── Core/
       │   ├── Config/             # Constants, environment config
       │   ├── Services/           # Firebase, auth, data services
       │   ├── Models/             # Shared domain models
       │   └── Extensions/         # Swift/SwiftUI extensions
       ├── Features/               # Feature modules (populated in later phases)
       ├── UI/
       │   ├── Components/         # Reusable UI components
       │   └── Theme/              # Colors, fonts, styles
       └── Resources/
           └── Assets.xcassets
       ```

    3. Add Firebase iOS SDK via Swift Package Manager:
       - Repository URL: https://github.com/firebase/firebase-ios-sdk
       - Add these products: FirebaseAuth, FirebaseFirestore, FirebaseStorage
       - Use the approach most reliable for CLI: either xcodegen spec with SPM packages, or use `swift package` tooling, or create the project via `xcodebuild` commands.

    4. Create Config.swift in Core/Config/:
       ```swift
       enum Config {
           static let appName = "Beer Glass Matcher"
           static let minimumIOSVersion = "16.0"
           static let bundleIdentifier = "com.beerglass.app"
       }
       ```

    5. Create a placeholder GoogleService-Info.plist in Resources/ with empty/dummy values so the project compiles. Add a comment in the file or a README noting it must be replaced with the real plist from Firebase Console.

    IMPORTANT: The recommended approach is to install xcodegen (`brew install xcodegen`) and use a project.yml spec file to generate the .xcodeproj. This is the most reliable way to create an Xcode project from the command line with SPM dependencies. If xcodegen is not available, create the project structure manually and use `xcodebuild` or open Xcode via `open` command.

    AVOID: Do NOT use CocoaPods (deprecated Dec 2026). Do NOT use file-type folder organization (Models/, Views/, ViewModels/ at root level).

<task type="auto">
  <name>Task 2: Configure Firebase initialization with AppDelegate and SwiftUI app entry point</name>
  <files>
    BeerGlassApp/App/BeerGlassApp.swift
    BeerGlassApp/App/AppDelegate.swift
  </files>
  <action>
    1. Create AppDelegate.swift in BeerGlassApp/App/:
       ```swift
       import UIKit
       import FirebaseCore

       class AppDelegate: NSObject, UIApplicationDelegate {
           func application(_ application: UIApplication,
                            didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]? = nil) -> Bool {
               FirebaseApp.configure()
               return true
           }
       }
       ```

    2. Update BeerGlassApp.swift (the @main entry point) to use UIApplicationDelegateAdaptor:
       ```swift
       import SwiftUI

       @main
       struct BeerGlassApp: App {
           @UIApplicationDelegateAdaptor(AppDelegate.self) var delegate

           var body: some Scene {
               WindowGroup {
                   ContentView()
               }
           }
       }
       ```

    3. Create a minimal ContentView.swift placeholder (will be replaced in Plan 02):
       ```swift
       import SwiftUI

       struct ContentView: View {
           var body: some View {
               Text("Beer Glass Matcher")
           }
       }
       ```

    IMPORTANT: Firebase MUST be initialized in AppDelegate.didFinishLaunchingWithOptions, NOT in View.onAppear (per research pitfall #1). Use @UIApplicationDelegateAdaptor pattern (per research Pattern 1).

    IMPORTANT: Add `FirebaseAppDelegateProxyEnabled = NO` to Info.plist to disable Firebase swizzling in SwiftUI context (per research pitfall #1).

    AVOID: Do NOT initialize Firebase anywhere other than AppDelegate. Do NOT use @ObservedObject for the app delegate -- use @UIApplicationDelegateAdaptor.
  </action>
  <verify>
    1. Run `xcodebuild build -project BeerGlassApp.xcodeproj -scheme BeerGlassApp -destination 'platform=iOS Simulator,name=iPhone 15'` -- build should succeed (may warn about missing GoogleService-Info.plist at runtime, but should compile)
    2. Verify AppDelegate.swift contains `FirebaseApp.configure()`
    3. Verify BeerGlassApp.swift contains `@UIApplicationDelegateAdaptor(AppDelegate.self)`
  </verify>
  <done>
    Project compiles with Firebase initialization configured. AppDelegate calls FirebaseApp.configure() on launch. BeerGlassApp.swift uses @UIApplicationDelegateAdaptor pattern. Info.plist has FirebaseAppDelegateProxyEnabled set to NO.
  </done>
