  <action>
Create `src/lib/firebase/glasses-db.ts` with client-side Firestore operations for the `users/{userId}/glasses` subcollection.

**Important:** This project uses client-side Firebase SDK (not Server Actions for Firebase calls). Auth happens client-side via `useAuth()` hook, so Firestore operations should also be client-side, consistent with the project pattern established in Phase 2.

**Type definition:**
```typescript
export type GlassInCollection = {
  id: string;
  glassType: string;    // References GlassType.id from catalog
  size: string;         // Selected size (e.g., "16oz")
  addedAt: Date;        // When added to collection
};
```

**Functions to implement:**

1. `getUserGlasses(userId: string): Promise<GlassInCollection[]>`
   - Query `users/{userId}/glasses` subcollection, ordered by `addedAt` desc
   - Use `getDocs()` (one-time fetch, not real-time)
   - Map Firestore Timestamps to Date objects
   - Return empty array if no glasses

2. `addGlassToCollection(userId: string, glassType: string, size: string): Promise<string>`
   - Add document to `users/{userId}/glasses` with `glassType`, `size`, and `addedAt: Timestamp.now()`
   - Return the new document ID
   - No duplicate check needed (presence-based, user can re-add if removed)

3. `removeGlassFromCollection(userId: string, glassId: string): Promise<void>`
   - Delete document at `users/{userId}/glasses/{glassId}`

4. `updateGlassInCollection(userId: string, glassId: string, size: string): Promise<void>`
   - Update the `size` field on document at `users/{userId}/glasses/{glassId}`
   - For editing glass size after adding

Import `db` from `@/lib/firebase/firestore`. Use Firestore methods: `collection`, `doc`, `getDocs`, `addDoc`, `deleteDoc`, `updateDoc`, `query`, `orderBy`, `Timestamp`.
  </action>

Run `npx tsc --noEmit` — no type errors. Verify the file exports all 4 functions and the GlassInCollection type.
  </verify>

  <action>
Create 6 React components for the glass management UI. All interactive components are Client Components ('use client') since they use hooks and event handlers.

**1. GlassCard.tsx** (Client Component — handles add/remove/size interactions)
- Props: `glass: GlassType`, `isInCollection: boolean`, `collectionEntryId?: string`, `selectedSize?: string`, `onAdd: (glassType: string, size: string) => Promise<void>`, `onRemove?: (glassId: string) => Promise<void>`, `onUpdateSize?: (glassId: string, newSize: string) => Promise<void>`
- Display: SVG illustration (use `<img>` tag with `src={glass.svgPath}`), glass name, one-liner description
- If NOT in collection: Show size selector (dropdown with `glass.availableSizes`, default to first), and "Add to Collection" button. One tap add — no confirmation. Button calls `onAdd(glass.id, selectedSize)`.
- If IN collection: Show current size, "Change Size" dropdown, and "Remove" button. Remove calls `onRemove(collectionEntryId)`.
- Use `useState` for local size selection and `isPending` loading state during async operations
- Disable buttons during pending state
- Card styling: `rounded-lg border border-gray-200 bg-white p-4 shadow-sm`. Image at top, text below, actions at bottom. Responsive: cards stretch to fill grid cell.

**2. GlassCatalog.tsx** (Client Component — needs to pass callbacks)
- Props: `userGlasses: GlassInCollection[]`, `onAdd: (glassType: string, size: string) => Promise<void>`
- Renders responsive grid: `grid grid-cols-1 gap-6 md:grid-cols-2 lg:grid-cols-3`
- Maps over `GLASS_CATALOG`, rendering a `GlassCard` for each type
- Determines `isInCollection` by checking if `glassType` exists in `userGlasses` array
- If glass is already in collection, passes `isInCollection: true` and the existing entry data

**3. GlassCollection.tsx** (Client Component — needs callbacks for remove/edit)
- Props: `glasses: GlassInCollection[]`, `onRemove: (glassId: string) => Promise<void>`, `onUpdateSize: (glassId: string, newSize: string) => Promise<void>`
- If `glasses.length === 0`, render `<EmptyCollection />`
- Otherwise render responsive grid with `GlassCard` for each glass in collection
- Enrich each `GlassInCollection` with catalog data via `getGlassType(glass.glassType)` for display info
- Grid styling same as catalog: `grid grid-cols-1 gap-6 md:grid-cols-2 lg:grid-cols-3`

**4. EmptyCollection.tsx** (Client Component — uses Link)
- No props required
- Centered layout with:
  - A glass icon (inline SVG or placeholder)
  - Heading: "You haven't added any glasses yet"
  - Subtext: "Start building your collection by browsing our catalog of beer glass types."
  - Prominent CTA button linking to `/glasses/catalog`: "Browse Catalog"
- Styling: `flex flex-col items-center justify-center py-12 text-center`

**5. GlassGuideCard.tsx** (Client Component — expandable detail + optional add button)
- Props: `glass: GlassType`, `showAddButton?: boolean`, `onAdd?: (glassType: string, size: string) => void`
- Displays detailed info: illustration (larger than GlassCard), name, full description, available sizes as tags, and beer style pairings as a list
- Expandable/collapsible detail section using `useState` for open/closed state
- When collapsed: shows glass name, illustration, one-liner
- When expanded: adds sizes, beer pairings, and optional "Add to Collection" button
- If `showAddButton` and `onAdd` provided: render inline size dropdown + "Add to Collection" button

**6. LoadingSkeleton.tsx** (Server Component — pure presentation)
- Export `GlassCardSkeleton`: animated placeholder matching GlassCard dimensions (`animate-pulse`, gray rounded boxes for image, title, description, button)
- Export `GlassCatalogSkeleton`: grid of 6 `GlassCardSkeleton` components matching catalog grid layout
- Styling: `animate-pulse rounded-lg border p-4` with `bg-gray-200` placeholder blocks

**Shared styling notes:**
- Use warm accent color `amber-600` for primary action buttons (matches beer culture aesthetic from PROJECT.md)
- Use `gray-50` backgrounds, `gray-200` borders for cards
- SVG images: `w-24 h-24 mx-auto mb-3` on cards, `w-32 h-32` on guide cards
- Keep all Tailwind classes inline (no separate CSS files)
