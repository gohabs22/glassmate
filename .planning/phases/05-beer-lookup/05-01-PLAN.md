      - `id: string` (kebab-case identifier, e.g., "pale-ale")

      - `description: string` (brief style description)
      - `exampleBeers: string[]` (2-3 well-known examples)

    - `BeerStyleCategory`: Grouping for style browser
      - `name: string` (category name, e.g., "Ales")

<task type="auto">
  <name>Task 2: Create beer style catalog and PunkAPI client</name>
  <files>src/lib/beer/styles.ts, src/lib/beer/api.ts</files>
  <action>
    **Create `src/lib/beer/styles.ts`:**

    Build a comprehensive hardcoded beer style catalog with 15-20 styles across 6 categories. Import BeerStyle and BeerStyleCategory from types.ts.

    Categories and styles (minimum coverage):
    - **Ales** (4-5 styles): Pale Ale, IPA, Amber Ale, Brown Ale, Red Ale
    - **Lagers** (3-4 styles): Pilsner, Helles, Dunkel, American Lager
    - **Stouts and Porters** (3 styles): Stout, Porter, Imperial Stout
    - **Wheat Beers** (2-3 styles): Hefeweizen, Witbier, American Wheat
    - **Belgian** (3 styles): Belgian Dubbel, Belgian Tripel, Saison
    - **Sours and Wild** (2 styles): Gose, Berliner Weisse

    Each style must have:
    - Meaningful description (1 sentence explaining the style)
    - 2-3 real, well-known example beers
    - Realistic ABV range

    Export:
    - `BEER_STYLE_CATEGORIES: BeerStyleCategory[]` - the full catalog
    - `getAllStyles(): BeerStyle[]` - flat list of all styles
    - `getStyleById(id: string): BeerStyle | undefined` - lookup by ID
    - `getExampleBeer(style: BeerStyle): Beer` - converts a style's first example into a Beer object (source: 'style-browse')

    **Create `src/lib/beer/api.ts`:**

    PunkAPI client for beer search. Base URL: `https://punkapi-alxiw.amvera.io/v3`

    Implement:
    - `searchBeers(query: string, signal?: AbortSignal): Promise<Beer[]>`
      - Uses `GET /beers?beer_name={query}&per_page=8`
      - Maps PunkAPI response fields to our Beer type:
        - `id` -> `String(punk.id)`
        - `name` -> `punk.name`
        - `style` -> derive from `punk.method` and `punk.description` (PunkAPI doesn't have a direct style field - extract from tagline/description, or default to "Craft Beer")
        - `abv` -> `punk.abv`
        - `ibu` -> `punk.ibu`
        - `description` -> `punk.tagline` (short) or `punk.description` (long - use tagline for search results, description for detail view)
        - `brewery` -> `"BrewDog"` (PunkAPI is BrewDog only)
        - `imageUrl` -> `punk.image_url`
        - `source` -> `'api'`
      - Returns empty array on error (don't throw - the UI will fallback to style browsing)
      - Respects AbortSignal for request cancellation
      - Catches AbortError silently (expected behavior)
      - Logs other errors to console

    Do NOT use @tanstack/react-query. Plain fetch with AbortController is sufficient for this use case.
  </action>
  <verify>
    `npx tsc --noEmit` passes.
    styles.ts exports BEER_STYLE_CATEGORIES with at least 6 categories and 15 total styles.
    api.ts exports searchBeers function.
    `getAllStyles().length >= 15` would return true.
  </verify>
  <done>Beer style catalog has 15-20 categorized styles with examples and ABV ranges. PunkAPI client maps BrewDog beer data to our Beer type with graceful error handling.</done>
