<objective>
Install beer lookup dependencies and create the beer data layer: type definitions, hardcoded style catalog, and hardcoded beer catalog with multi-field search.

Purpose: Establish the typed data foundation that all beer search, browse, and display components depend on. Without this layer, no beer lookup UI can function.
Output: Three library files (types, styles, catalog) and new npm dependencies installed.

**DATA SOURCE NOTE:** CONTEXT.md specified OpenBreweryDB as the data source, but research (05-RESEARCH.md) confirmed that OpenBreweryDB ONLY contains brewery facility data (addresses, phone numbers, website URLs) — it has NO beer data (no beer names, ABV, IBU, styles). No free comprehensive beer API exists. As a pragmatic compromise, we use a hardcoded beer catalog of ~50-100 real beers across all major styles. This satisfies the phase goal ("drinkers can search for beers and view beer information") and enables multi-field search (beer names + brewery names + style keywords) as CONTEXT.md specifies, without any API availability dependency.
</objective>

      - `id: string` (kebab-case identifier, e.g., "pale-ale")
      - `name: string` (display name, e.g., "Pale Ale")

      - `exampleBeers: string[]` (2-3 well-known examples)

    - `BeerStyleCategory`: Grouping for style browser
      - `name: string` (category name, e.g., "Ales")

    **Create `src/lib/beer/styles.ts`:**

    Build a comprehensive hardcoded beer style catalog with 15-20 styles across 6 categories. Import BeerStyle and BeerStyleCategory from types.ts.

    Categories and styles (minimum coverage):
    - **Ales** (4-5 styles): Pale Ale, IPA, Amber Ale, Brown Ale, Red Ale
    - **Lagers** (3-4 styles): Pilsner, Helles, Dunkel, American Lager
    - **Stouts and Porters** (3 styles): Stout, Porter, Imperial Stout
    - **Wheat Beers** (2-3 styles): Hefeweizen, Witbier, American Wheat
    - **Belgian** (3 styles): Belgian Dubbel, Belgian Tripel, Saison
    - **Sours and Wild** (2 styles): Gose, Berliner Weisse

    Each style must have:
    - Meaningful description (1 sentence explaining the style)
    - 2-3 real, well-known example beers
    - Realistic ABV range

    Export:
    - `BEER_STYLE_CATEGORIES: BeerStyleCategory[]` - the full catalog
    - `getAllStyles(): BeerStyle[]` - flat list of all styles
    - `getStyleById(id: string): BeerStyle | undefined` - lookup by ID
    - `getExampleBeer(style: BeerStyle): Beer` - converts a style's first example into a Beer object (source: 'style-browse')

    **Create `src/lib/beer/catalog.ts`:**

    Hardcoded beer catalog with ~50-100 real, well-known beers and a multi-field search function. Import Beer from types.ts.

    Build `BEER_CATALOG: Beer[]` array containing real beers distributed across all major styles. Include beers from diverse breweries (not just one brand). Each beer entry:
    - `id`: kebab-case unique identifier (e.g., "guinness-draught")
    - `name`: real beer name (e.g., "Guinness Draught")
    - `style`: matching style name from styles.ts (e.g., "Stout")
    - `abv`: real ABV value
    - `ibu`: real IBU value (or null if not commonly known)
    - `description`: one-sentence description of the beer
    - `brewery`: real brewery name (e.g., "Guinness")
    - `imageUrl`: null (no images for hardcoded data)
    - `source`: 'catalog'

    Aim for good coverage: at least 3-5 beers per style category, including popular craft and macro beers that real users would search for. Examples:
    - Ales: Sierra Nevada Pale Ale, Lagunitas IPA, Fat Tire Amber Ale, Newcastle Brown Ale, etc.
    - Lagers: Pilsner Urquell, Budweiser, Corona Extra, Modelo Especial, etc.
    - Stouts: Guinness Draught, Founders Breakfast Stout, Left Hand Milk Stout, etc.
    - Wheat: Blue Moon, Weihenstephaner Hefeweizen, Hoegaarden, etc.
    - Belgian: Chimay Red, Westmalle Tripel, Saison Dupont, etc.
    - Sours: Anderson Valley Gose, Berliner Kindl Weisse, etc.

    Implement search function:
    - `searchBeers(query: string): Beer[]`
      - Case-insensitive search across THREE fields: `name`, `brewery`, AND `style`
      - A beer matches if the query appears as a substring in ANY of these three fields
      - Return up to 8 results
      - Sort by relevance: exact name match first, then name starts-with, then name contains, then brewery/style matches
      - Empty/short query (< 2 chars) returns empty array
      - This is synchronous (in-memory filtering) - no async, no AbortController needed

    Do NOT create src/lib/beer/api.ts. There is no external API. All beer data is local.
  </action>
